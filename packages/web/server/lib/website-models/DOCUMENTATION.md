# Website account model providers

The Mac opts in through desktopWebsiteModels. Standalone servers do not. Managed native providers use the same private local callback token as the existing managed child, validated with agentToolRuntime.authorizeRequest. Completion routes register before UI auth and enforce their own per-child auth, exact loopback peer and enterprise gate. Worker routes register after normal UI auth, additionally require loopback, and grant a unique lease per job. Paired clients use normal native session APIs, not worker/account credentials.

The provider converts text transcripts and offered tool definitions into a website prompt. It rejects nontext/oversized requests, never trims context silently, and never calls a paid provider. Fresh requests start a new website chat. Gemini tool continuations reuse only the exact observed chat URL linked to the preceding native assistant response and transcript. The worker verifies its user-message count and last-answer hash before sending, and reads only an answer after the newly acknowledged user message. Missing, expired or changed continuation state fails without creating another chat. Venice still starts fresh for each request. Responses become normal compatible chat completion records/SSE chunks. Strict JSON tool calls must name only offered tools with object arguments; execution and permission checks remain with OpenCode. Unknown/invalid calls fail. Refusals remain plain text. Token usage is unknown and not fabricated.

Gemini allows at most four tool rounds per user turn, then one answer-only generation with no tools offered. Repeating the same tool name and JSON arguments within a turn, including a duplicate within one batch, fails before any repeated call is returned for execution. A tool round retains the existing eight-call batch limit. Each job attempts Send once. Website errors, uncertain sends and malformed compaction replies never trigger regeneration. An identical model/transcript request is rejected with nonretryable HTTP 422 for ten minutes, regardless of stream mode or earlier success, failure or cancellation. The bridge has no native session identifier in this compatible request, so indistinguishable transcripts from separate sessions are conservatively treated as duplicates. A new user message changes the transcript and can proceed. The guard retains at most 128 recent attempt hashes and bounded observed continuation metadata in memory, never credentials or transcript bodies, and clears them on shutdown. At capacity it refuses new requests rather than evicting retry protection.

The broker holds at most eight requests, runs one per provider, bounds request/worker lifetimes, rejects stale leases and cleans up on abort/shutdown. An unresolved website error is nonretryable at the HTTP boundary; the bridge never repeats a submitted website message. Accounts may still impose quotas or refuse requests. Text, ordinary document-text input and tool calls use this path; native image/audio model input/output is not advertised. Website-specific media and account settings remain on the explicit account-connection page.
